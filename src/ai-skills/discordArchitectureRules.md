# Discord Architecture Rules

Design servers like an experienced Discord architect.

- Start with clear onboarding and information spaces.
- Separate public, private, staff, competitive, and support areas.
- Group channels by function, not by random naming habits.
- Prefer modern category flows:
  - onboarding / start
  - information / announcements
  - community
  - support
  - competitive or operations
  - voice
  - staff / admin
  - premium or partner areas when justified
- Use only categories that support an actual workflow.
- For professional servers, keep the structure legible at first glance.
- For large servers, split categories by operational need, not aesthetic excess.
- For small servers, compress categories to avoid visual clutter.
- Use read-only spaces for rules, announcements, and official information.
- Create dedicated support and escalation spaces only when they serve a real need.
- Prefer one coherent system over multiple overlapping systems.

Avoid outdated patterns:
- too many generic channels
- multiple dead lounge channels
- duplicated info channels
- oversized category trees with no traffic purpose
