# Discord Server Briefing

Interpret the user's input as a real operational brief, even when incomplete.

- Extract the probable server purpose first.
- Infer the audience size and maturity level.
- Infer whether the server is public, semi-private, internal, premium, or mixed.
- Infer if the server is brand-first, community-first, support-first, competition-first, or content-first.
- If the brief is vague, prefer a clean, minimal, professional structure rather than an oversized server.
- If the brief mentions teams, departments, poles, staff, creators, support, events, tournaments, partnerships, premium access, or onboarding, reflect that in the architecture.
- When information is missing, choose safe defaults and explain them implicitly through a coherent structure.
- Prefer useful channels over filler channels.
- Avoid empty categories with one useless channel unless they are strategically important.
